Treat it as a living document. After every 3–4 sprints, review it together and adjust. --- ## Roles | Role | Who | Responsibilities | |---|---|---| | **Product Manager** | You | Decides what gets built, sets priorities, owns the vision, manages the backlog | | **Scrum Master** | Claude | Runs sprint planning, tracks progress, removes blockers, keeps the process honest, calls out scope creep | | **Tech Lead / Dev Manager** | Claude | Makes architectural decisions, reviews technical approach before code is written, unblocks implementation problems | | **Developer** | You | Writes all code with Claude's guidance at every step | | **UX Designer** | You, guided by Claude | Makes visual and interaction decisions; Claude flags anything that violates the dementia-informed design rules in the spec | | **QA Tester** | You + your mom + your dad + your sister | You test every feature before it ships; your mom's confusion is a bug; your dad and sister test the admin website as real users and report what's confusing or broken | | **Admin Testers** | Your dad + your sister | First real users of the admin website — they upload content, write stories, and manage the patient profile exactly as they would in real life; their feedback on the admin experience is as important as your mom's feedback on the patient experience | | **Content Manager** | Your dad + your sister | Responsible for gathering and uploading real content — family photos, song clips, personal stories, people profiles; this should not fall on you as the developer | | **Legal Reviewer** | You (before public launch) | Must review and approve privacy policy and terms of use before the app is used by anyone outside your immediate family; not urgent for MVP but required before public distribution | | **Primary Stakeholder** | Your mom | The definition of success. People can find it, understand what you're building, and submit suggestions. This is your public signal that this project is real. **Tasks:** - [ ] Create a GitHub account if needed; create a new repository called `the-memory-album` - [ ] Set up GitHub Codespaces on the repository (browser-based VS Code — no installs required) - [ ] Create a Vercel account at vercel.com and connect it to the GitHub repository - [ ] Point TheMemoryAlbum.com (GoDaddy) to Vercel using DNS settings - [ ] Build a single-page HTML landing page with: - App name and brief description ("A personalized daily memory app for your loved one") - "Coming Soon" messaging - A simple suggestion/feedback form (using Formspree.io — free, no backend required) - Your contact email or a way to follow progress - [ ] Deploy it — TheMemoryAlbum.com goes live **End of sprint deliverable:** A real, live website at TheMemoryAlbum.com that you can share with anyone. Share it. Send it to family. Post it wherever you want. Start collecting suggestions. **Notes:** This sprint is intentionally lightweight on technical complexity. The goal is momentum and a public presence, not infrastructure. Formspree handles the suggestion form submissions and emails them to you — zero backend code required. --- ### Sprint 2 — Foundation **Goal:** Replace the landing page with a real Next.js application. Visiting /dashboard shows a placeholder. Visiting /play shows a placeholder. The app is scaffolded and ready to build on. --- ### Sprint 3 — Auth + Data Schema **Goal:** Secure login for family admins. Full Firestore data structure created. The patient profile creation wizard works. All data structures exist in Firestore (empty, but correctly shaped). --- ### Sprint 4 — Admin: People Upload **Goal:** Family members can be added with photos, names, relationships, and bios. Anyone can download it. Your mom can find it by searching. --- ## After Sprint 15: Ongoing From here the work shifts from building to improving. At the start of each sprint, Claude (as Scrum Master) will confirm the goal, review any carryover from last sprint, and set the task list. At the end of each sprint, we do a brief retrospective — what got done, what didn't, and why. **You are the Product Manager.** You decide what matters and when. If you want to change priorities, change them — but tell Claude first so the plan can be updated. **Claude is the Scrum Master and Tech Lead.** Before each sprint begins, Claude will review scope and flag anything unrealistic. During the sprint, Claude guides every technical decision. If a sprint runs over, Claude will help you decide what to cut or carry forward — not just pile it on top of next sprint. **Never start a sprint cold.** Begin every coding session by telling Claude which sprint you're on and which specific task you're attempting. Paste the relevant section of the technical spec. Get the approach confirmed before writing code. **Never spin on a problem.** If you're stuck for more than 20 minutes on anything, stop and ask. Paste the error exactly as it appears. Describe what you tried. You will get unstuck faster this way than grinding alone. **Small commits, always.** Push to GitHub at the end of every working session even if the feature isn't finished. Never lose work. **Your mom's reaction is the sprint review.** When a feature involves the patient experience, test it with her. Her confusion is a bug. Her engagement is a green light. --- *Project Plan v1.0 — Living document. Revisit and adjust every 3–4 sprints.* *Next review point: End of Sprint 4.*
